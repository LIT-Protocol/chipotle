# Customer-path QA, round 3 — 2026-09-17

Third black-box pass over https://keychain.litprotocol.com/ as a brand-new user, following
the published [SKILL.md](https://keychain.litprotocol.com/SKILL.md) (2.0.5) and the
developer docs, against production. Same rules as the earlier rounds
([one](user-qa-2026-09-16.md), [two](user-qa-2026-09-16-round2.md)): published docs and
npm only, a fresh wallet that had never seen Keychain, dummy secret values, no payment.
Repository code was read only after the findings were recorded, to implement the fixes.

## What was exercised against production

- Fresh `npm install @lit-protocol/keychain@2.0.5` (19 MB, Node 22): `--help`, `--version`,
  `init` (0600, refuses to overwrite), `actions`, `attest` (all six checks pass in ~1 s).
- **New account** with a never-used wallet (mock EIP-1193 wallet in headless Chromium):
  first sign-in provisioned the vault in 24 s; returning sign-ins 1.8 s. The app reopens
  the tab that was active at sign-out.
- Stored secret: lowercase name `my_key` is accepted and upper-cased to `MY_KEY`; create,
  approve two agents, download config; CLI `get` (1.9 s), `run` (env, `--env`, `--file`
  0600 and removed afterwards, exit status propagated), SDK `list`/`get`/`describeCredential`,
  MCP `initialize`/`tools/list`/`list_secrets`/`get_secret`/`agent_public_key` with one
  and with two config files.
- Access control: unapproved identity → `not approved` naming the key; **Revoke** → the
  revoked agent is denied; **Disable** → every agent gets `owner disabled`; **Enable**;
  **Rotate & approve** → the pre-rotation config reads the new value, agent list intact,
  expiry preserved; **Never expire** → "Permission never expires"; **Renew** 0 rejected
  (`min=1`), 3650 accepted.
- Connected service: OpenAI with a syntactically valid fake key; malformed credential
  refused client-side with the accepted pattern shown; `get` on it points at `use`;
  `use` with missing/partial input lists exactly the missing fields; `use` with valid input
  returns the "Lit ran the action but it did not complete" explanation; `run` on a
  service-only config says there is nothing to inject; MCP `openai_chat` mirrors the CLI.
- **Replace execution key** → old config gets the 401 "owner most likely replaced it" hint;
  freshly downloaded config works.
- Filled the Free plan to 5/5 secrets. Backup download, Activity, Recovery & backups, all
  footer links (`SKILL.md`, `llms.txt`, `SECURITY.md`, npm, source).
- Google sign-in and passkeys were not repeated this round (headless; passkeys passed in
  round 2). No real provider credential was used, so a successful `use` remains unverified.

## Observations not changed here

- **Activity** still lists only event kinds and times (`Policy Updated` ×13 during this
  session) with no secret or agent name, so it cannot answer "what did I just do to which
  secret". Needs a schema change (round 2 note stands).
- **No way to delete or archive a secret.** Five throwaway values fill the Free plan for
  good; the new explanatory text (fix 3) softens this but the product question remains.
- Stripe Checkout is a live-mode session for "Workgraph, Inc" (account configuration).
- WalletConnect project id is still the placeholder, so only injected wallets are offered.
- The name field's `title` says "Letters, digits and underscores only" without mentioning
  that lowercase is upper-cased on save; harmless since the transform is silent and correct.
- Revoke acts immediately with no confirmation. Reasonable for a reversible action, noted
  because Export secret does confirm.
- Approving an agent and every policy change takes ~3 s; secret creation ~10 s; first
  sign-in 24 s with progress text. All within expectations.
