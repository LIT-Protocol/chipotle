# Live agent discovery implementation plan

1. Add failing authenticated discovery and same-client lifecycle tests. Reuse canonical SHA-256 / Ed25519 signing and current owner-receipted policies; do not change action sources or lock/archive.
2. Add service-audience-bound, 60-second one-use challenges in PostgreSQL, atomically consumed after strict signature validation, with global/peer rate budgets and expiry cleanup. Discovery returns only currently granted locators and per-vault execution-only billing bootstrap for those vaults, never master keys, private keys or plaintext. Validate signed manifests/envelopes/policies and current operation/version/hash on the backend before disclosure.
3. Add `LiveKeychain` (identity plus default/configured service origin, separately trusted Lit origin). Each list/get/use discovers again and verifies bundles directly against pinned Lit. Keep legacy `Keychain` / static exports compatible. Use stable vault/secret qualified identifiers; bare names only when unique. Never cache authorization or discovered inventory between operations.
4. Wire configless CLI list/get/use/run and MCP; retain explicit legacy config-file paths. Change onboarding completion to ready-to-use with optional advanced export. Update SDK/docs/SKILL, registry-checked version and packed publish gate.
5. Run build, unit/security tests, isolated owner UI, Rust fmt/clippy/tests and local PostgreSQL integration/runtime where available. Record exact blockers; no production fallback, push, merge or npm publication.

Security boundary: discovery authenticates metadata/bootstrap only, not secret authority. Every use still carries the agent signature and is authorized by the immutable owner-verifying Lit action. Scoped execution billing keys are reusable billing credentials (already the static config model), not owner sessions or authority; a previously approved agent retaining one may consume sponsored execution but cannot bypass an honest current policy. Revocation applies on the next lookup, not to already released plaintext or authorized in-flight calls. DB rollback remains the documented operator trust. Service responses cannot change the client's trusted Lit origin.
